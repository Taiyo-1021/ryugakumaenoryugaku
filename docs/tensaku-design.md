# 週末テスト（確認テスト）添削ツール 設計メモ

週末テストの添削から生徒への公開までの仕組みと、これまでに決めたことをまとめたメモです。
コードを読まなくても全体がわかること、別のセッションからでも続きができることを目的にしています。

- 対象のファイル：`tensaku-tool.html`（添削ツール）、`notion-relay.gs`（中継）、`forms/week2-kakunin-form.gs`、`week2-kakunin-listening.html`、`week1-kakunin-sokuji.html`・`week2-kakunin-sokuji.html`
- 講師向けの使い方：講師マニュアル（Claude の Artifact「確認テスト 講師マニュアル」）。Week2 と課題の流れはまだ反映していない

## 1. 全体構成

| 部品 | 役割 |
|---|---|
| 添削ツール `tensaku-tool.html` | GitHub Pages の静的ページ（https://taiyo-1021.github.io/ryugakumaenoryugaku/tensaku-tool.html）。講師が点数・判定を入れ、AI に渡す文を作り、AI の返事を読み戻す。点数と補助教材の判定はツールが計算する。入力途中の内容はブラウザ（localStorage `tensaku-tool-v2`、キーは `週\|生徒`）に保存。中継の URL と合言葉も localStorage（`tensaku-tool-relay`）にだけ置く |
| AI | ツールは AI の API を呼ばない。講師が「AI用にコピー」で自分の AI に貼り、返事（【A】表と【B】本文）をツールに貼り戻す。Part 2 の録音の文字起こしは各講師の Notta |
| 中継 `notion-relay.gs` | Google Apps Script のウェブアプリ（単独プロジェクト「確認テスト中継」、オーナーの Google アカウントで動く）。ツールからの POST を受けて、記録シートへの書き込み、Notion の下書き作成、生徒ページへの公開、フォーム回答の読み込みをする。Notion の鍵はここのスクリプトプロパティにだけ置く |
| 記録シート | Google スプレッドシート。全生徒・全週の結果を1か所に残す。A〜K 列を中継が書き、M 列から右は集計の数式（中継は触らない） |
| Notion | 「確認テストFB」データベースに下書き（講師だけが見る）。生徒ごとの「○○さんのフィードバック」ページ（Web 公開）の下に、週ごとのページを公開する |
| Google フォーム | Part 1（Week2 は Part 1 と Part 3② リスニング）の回答。回答シートは中継が読む |
| Google ドライブ | テストの PDF、週ごとのフォルダ、回答シート、記録シート。PDF は GitHub には置かない |
| Canva | テストの PDF を作る。PDF のダウンロードと差し替えはユーザーが手で行う |
| Slack | 生徒は「テスト提出部屋」に提出する。講師は公開後に、ツールが作った文面とリンクを送る |

### 中継の action

| action | すること |
|---|---|
| （なし） | 「記録してNotionに下書きを作成」。記録シートに Part 1〜4 の行を書き（同じ週・生徒の行は置き換え）、Notion に下書きを作る。下書きを講師が直していたら、消す前に確認する |
| `part1` | フォームの回答シートを読む。名前に「確認テスト」を含み、フォームにつながったシートだけ。名簿と似た名前も返す |
| `drafts` | その週に下書きがある生徒の一覧 |
| `publish` | 「生徒に公開」。下書きを生徒専用ページの下にコピーし、スピーキングのポイント（Part `S`）と課題（Part `T`）を記録シートに書く |

スクリプトプロパティ：`NOTION_TOKEN`・`NOTION_DB_ID`・`PASSCODE`・`SHEET_ID` はユーザーが入れる。`STUDENT_ROOT_ID`・`STUDENT_PAGE_<名前>`・`DRAFT_DONE_<ページID>` は中継が自分で保存する。

### 記録シートの列（A〜K）

週、生徒、担当、Part、問、回答、直した文、瞬発力、点数、弱点タイプ、講師メモ

Part の値：`1`〜`4` は各 Part。`S` はスピーキングテストの意識するポイント（できた 1／まだ 0）。`T` は次週の課題（やる 1／お休み 0）。Week2 では音読の評価箇所（`音読：観点／項目`、`音読（追加）`）とリスニング（L1〜L6）の行も入る。

### 1週間の流れ

1. 生徒が週末テストを提出する（フォーム・Slack）
2. 講師がツールで採点し、AI にコメントを書かせる
3. 「記録してNotionに下書きを作成」で、記録シートと Notion の下書きができる
4. 講師が Notion で下書きを直す
5. レッスンで下書きを画面共有し、次週の課題を生徒と決め、スピーキングテストをする
6. 講師が録画を見て「意識するポイント」にチェックをつけ、「次週の独り言で意識すること」を書く
7. ツールの「生徒に公開」で、生徒専用ページにコピーされる
8. 講師がツールの作った文面を Slack で送る

## 2. 決定事項

### 補助教材のライン（9割）

- 9割未満なら補助教材「あり」。7割 → 8割 → 9割と引き上げてきた（2026-10-10 に9割に決定）
- Week1：Part 2（瞬間英作文）17/20 以下、Part 3（発音）15/17 以下
- Week2：瞬間英作文・音読とも 17/20 以下（`WEEKS["Week2"].supportLine`）
- Part 1 とリスニングは判定に使わない
- ラインは週ごとに `supportLine` で変えられる。ない週は `SUPPORT_LINE` を使う

### 水曜締め切り

- レッスンと公開は水曜の夜までに終える
- 水曜までにレッスンができなかった生徒は、最初に入っているチェック（課題）のまま確定し、講師がそのまま公開する
- 運営が見るのは「水曜の夜までに全員の公開が終わっているか」だけ。カレンダーは使わない

### 次週の課題の決め方

- Step1〜3 は日曜の朝に全員に配る
- 下書きの「📚 WeekNの課題」に、Step1〜3 と補助教材のチェック欄が入る。Step は最初からチェック、補助教材はテストが9割未満なら最初からチェック
- レッスンで生徒の生活に合わせてチェックを付け外しする。公開すると記録シート（Part `T`）と Slack の文面に入る（お休みのものは「➖ Step2（今週はお休みでOK）」のように出る）
- 教材リンクは `TASK_LINKS` に週ごとに入れる（Step1〜3・瞬間英作文・発音の3種類）。まだ空

### 生徒名の扱い

- 名前の空白（半角・全角）は取り除いて同じ人として扱う。「さん」は付けない
- 初めての名前が既存の名前と似ていたら（片方がもう片方を含む、旧字体・異体字、カタカナとひらがな、1文字違い）、書き込む前に「同じ人ですか？」と確認する
- 他の生徒の名前を生徒に見せない。フォームに名前のプルダウンは作らない
- 講師は全生徒の名前を見てよい。ツールでは名簿（生徒ページと記録シートの名前）から生徒をプルダウンで選ぶ
- 週は日付から自動で選ばない。全週の回答一覧から回答を選ぶと、週と生徒名が切り替わる

### 公開の流れ

- 下書き（講師だけ）→ 講師が直す → レッスン → 生徒に公開、の順。下書きには講師が書く欄の初期の文があり、残っていると公開できない
- 生徒ごとに専用ページを作り、そのページ単位で Web 公開する（読み取りのみ、編集・複製・検索エンジンはオフ）。Web 公開は Notion の API でできないので、新しい生徒のときだけ手でオンにする
- もう一度公開すると、同じリンクのまま中身だけ入れ替わる
- スピーキングFB は記録シートに残さない。「録画を確認した」のチェックは使わない

### 誰が何を見られるか

- 生徒は自分のページだけを見る。他の生徒の FB が見えるのは困るので、生徒ごとに公開している
- 講師は自分が担当した生徒のフィードバックだけを見る（**要確認**：前のセッションではこの決め方が見つからなかった。いまは Notion が無料プランで講師はフルアクセスのゲストのため、全員の下書きが見える。制限するには Plus プランが要る。ユーザーは「記録自体は記録シートに残ってるので大きな問題ではない」と話していた）

### Week2 で決めたこと

- Part 1：和文英訳24問。その問題で問う文法が使えていれば1点（単語や冠詞のミスは減点せず FB で直す）。AI が判定し、講師が○×で直せる
- Part 3① 音読：5観点（流暢さ・個別の音・リンキング・アクセント・リズムと抑揚）×4項目で 20点。生徒には評価項目を知らせない
- Part 3② リスニング：6問、フォームから自動採点。本文の暗記で解けないよう話題を変えた。再生は1問2回まで。「TOEIC」という言葉は使わず「4択」と書く

## 5. 気をつけること

- `notion-relay.gs` を変えたら、Apps Script の「コード.gs」に全部貼り付け、「デプロイを管理」→ 鉛筆 →「新バージョン」でデプロイし直す。「新しいデプロイ」にすると URL が変わり、ツールの設定を全員変えることになる
- 「確認テスト中継」プロジェクトに別のスクリプト（フォームを作るものなど）を入れない。中継が上書きされたことがある
- Notion の「確認テストFB」の列名を変えるとツールが動かなくなる
- フォームの質問の順番を変えると採点がずれる
- 新しい週を足すときは `tensaku-tool.html` の `WEEKS` に追加する（回答シートの ID、問題、補助教材のライン）
